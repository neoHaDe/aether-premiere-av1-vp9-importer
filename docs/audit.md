# Аудит Aether 1.3.0

Дата: 2026-08-25  
Объект: репозиторий `aether-premiere-av1-vp9-importer` (ветка `master`, релиз 1.3.0)  
Общая оценка: **7.5 / 10**

Зрелый нативный импортёр AV1/VP9 для Premiere Pro, After Effects и Media Encoder. Архитектура продуманная, тесты и история коммитов показывают, что гонки, переполнения и падения хоста уже ловили. Критических секретов в репозитории нет.

Главный риск — не «дыры в приложении», а **разбор чужих медиафайлов внутри процесса Adobe** без жёсткого белого списка протоколов и форматов FFmpeg.

| Область | Оценка |
|---|---|
| Архитектура | Ядро (`AV1Decoder`) отделено от SDK (`AV1Importer` / `AV1Async`). CEP-панель не дублирует логику, а вызывает `AetherDiagnose.exe`. |
| Чистота кода | Сильные комментарии «почему», безопасные копии строк, насыщение длительности, раздельные замки видео/звука, ASan и fuzz в CI. |
| Секреты | Хардкода паролей, токенов и API-ключей нет. `installer/signing/` в `.gitignore`. |
| Безопасность | Нет XSS в панели, `execFile` без оболочки. Пробелы: FFmpeg без `protocol_whitelist`, перехват всех MP4/MKV, fallback `LoadLibraryW`, неподписанный установщик с правами администратора. |
| Мусор | Случайных `.env` / `.log` / ключей в дереве нет. |

## Критические и высокие проблемы

### 1. FFmpeg открывает файлы без белого списка протоколов и форматов — высокий

`Decoder::Open` вызывает `avformat_open_input` без опций:

```cpp
int err = avformat_open_input(&fmt_, utf8Path.c_str(), nullptr, nullptr);
```

В коде нет `protocol_whitelist`, `format_whitelist`, отключения сети. По умолчанию FFmpeg умеет `http`, `concat`, внешние ссылки в контейнерах. Плагин живёт **внутри Premiere** с правами пользователя: вредоносный клип может уйти в SSRF, чтение чужих файлов или лишний парсер.

Нужно:

- `protocol_whitelist=file`
- `format_whitelist` под MP4/MOV/Matroska/WebM
- запрет внешних data references в MOV
- ограничение `probesize` / `analyzeduration`

То же самое относится ко второму открытию контейнера в `OpenAudio`.

### 2. Приоритет 100: FFmpeg разбирает почти любой импортируемый контейнер — высокий

Плагин объявляет `mp4/mkv/webm/mov/m4v/mka` с приоритетом **100**, выше штатных импортёров Adobe. Чужой кодек потом возвращается через `imBadFile`, но **контейнер уже разобран** `avformat_open_input` + `avformat_find_stream_info`.

Атакующему не обязательно подсовывать AV1: достаточно обычного MP4 на таймлайн. Поверхность — любой файл этих расширений, не только «свои» кодеки.

Это ещё и производительность: на каждой импортируемой H.264-шке плагин отрабатывает probe, потом честно отказывается.

### 3. Нет верхней границы размеров кадра — высокий, DoS

После открытия в `info_.width` / `info_.height` попадают сырые поля контейнера. Проверка «кадр без размеров» есть (`ToSystemMemory`), лимита «не больше N» нет.

Диагностика выделяет буфер без потолка:

```cpp
const int stride = mi.width * 4;
std::vector<uint8_t> buf((size_t)stride * mi.height);
```

`fuzz_test` сам режет размер до 8192, прод-путь — нет. Файл с гигантским `width×height` может исчерпать память процесса Adobe (панель, `Aether.exe`, сам Premiere).

Счёт кэша тоже уязвим к переполнению на экстремальных размерах:

```cpp
const size_t bytesPerFrame = (size_t)info_.width * info_.height * 3 / 2;  // NV12
cacheBudget_ = bytesPerFrame * 60;
```

### 4. Fallback `LoadLibraryW` — риск DLL hijacking — высокий вне «чистой» установки

Сначала DLL грузятся из папки плагина (`LOAD_WITH_ALTERED_SEARCH_PATH`) — это правильно. Если рядом нет файла, идёт обычный поиск по имени:

```cpp
m = LoadLibraryW(name);
```

В установленной раскладке DLL лежат рядом с `.prm`. В dev / portable / неполной установке загрузчик может подхватить чужую `avcodec-62.dll` из каталога Premiere, cwd или PATH. Для импортёра в чужом процессе это подмена кода.

Надёжнее: только полный путь; при отсутствии DLL — отказ.

### 5. Установщик не подписан и требует администратора — высокий для цепочки поставок

Осознанно описано в README. `AetherSetup-*.exe` ставит DLL в общую папку Adobe и CEP-расширение с Node.js. Компрометация релиза GitHub = код в процессе Premiere у всех, кто поставил.

Смягчения уже есть: исходники открыты, SHA256 релизов, пиннинг FFmpeg и `ZXPSignCmd` по SHA256, воспроизводимый portable zip. Не хватает Authenticode.

### 6. CEP: Node.js + mixed-context — средний/высокий по модели, сейчас не пробит

```xml
<Parameter>--enable-nodejs</Parameter>
<Parameter>--mixed-context</Parameter>
```

Любой XSS в панели стал бы RCE (файловая система, `execFile`). Сейчас вывод идёт через `textContent`, JSON диагностики экранируется, процессы запускаются через `execFile`, путь в PowerShell — через `-LiteralPath $args[0]`. Это аккуратно.

Остаётся: панель с правами Node, запуск `AetherDiagnose.exe` по пути из реестра/`Program Files`, пользовательский файл как аргумент. Нет CSP в HTML. Для CEP это типично, но привилегии широкие.

## Архитектура и качество кода

### Сильные стороны

- Чёткое разделение: декодер не знает SDK; тесты (`decoder_test`, `host_test`, `plugin_test`, `fuzz_test`) гоняются без Premiere.
- Гонки и UAF уже разбирались: раздельные mutex видео/звука, `errorMutex_`, `CallGuard` / `inFlight` в async, набор замков на `EnsureDecoder`.
- Безопасные копии: `CopyUtf16` не молчит при обрезке пути; `strcpy_s` / `wcscpy_s`; насыщение `vidDuration`.
- Наборы Premiere берутся с перебором версий и отдаются той же версией; нулевая версия = «не брали».
- Один номер версии в `AV1Version.h`; установщик и панель читают его из собранного `.prm`.
- Комментарии фиксируют реальные баги (AMF падает, P010 без буфера, DllMain + LoadLibrary).

### Технический долг и логические ограничения

| Тема | Суть |
|---|---|
| Поворот | Поле есть, кадр отдаётся неповёрнутым — в SDK импортёра нечем объявить. |
| P010 | Код жив, по умолчанию выключен: Premiere 26 формат принимает, буфер не даёт. |
| Два декодера на клип | Async по правилам SDK не может ссылаться на обычный — удвоение памяти/открытий. |
| Два `avformat_open_input` | Видео и звук — отдельные контейнеры, чтобы seek одного не сбивал другое. Цена — лишний I/O. |
| INI | Логика разъехалась: JS `updateDecodeMode`, C++ `SetIniValue`, плюс три почти одинаковых разбора файла. |
| `WideCharToMultiByte(CP_ACP)` | В `DisabledUnlessTurnedOn` для env; ядро использует `getenv`. На не-ASCII значениях поведение разъедется. |
| Журнал | `fflush` после каждой строки (осознанно). На плотном playback всё ещё стоимость. `LogPath` чистит только `%USERPROFILE%`, не имя пользователя отдельно. |
| `ticksPerFrame` | `ticksPerSecond * fpsDen / fpsNum` без защиты от переполнения на безумном FPS из файла. |
| GUID | `AppId` и `ProjectGuid` содержат не-hex (`AV01` / `AV11`). Как строки работают, как GUID — нет. |

Логических «бомб» уровня «пишем мимо буфера хоста молча» в текущем коде мало: проверка `rowBytes`, знаковый stride, отказ при слишком длинном пути, защита `GetAudio` по числу каналов — всё уже чинилось.

## Безопасность (сводка)

**Секреты:** не найдены. Пароль CEP-сертификата генерируется криптографически и пишется в `installer/signing/password.txt` вне git. Минус сборки: пароль передаётся в argv `ZXPSignCmd` (виден в списке процессов на машине релиза).

**Инъекции / XSS:** панель не клеит HTML из отчёта; `innerHTML` только очищает контейнер. PowerShell не интерполирует путь в скрипт.

**Зависимости:** FFmpeg 8.1.x с GitHub BtbN, SHA256 в CI. `ZXPSignCmd` — commit + SHA256. Actions закреплены по хешу коммита, не по тегу. Аудиокодеки **не** ограничены списком (берётся любой декодер FFmpeg) — лишняя поверхность после открытия контейнера.

**Приватность:** диагностика заменяет профиль, user, machine; журнал — в основном профиль. `Scrub` чувствителен к регистру; короткие имена не чистятся. Пути вне `%USERPROFILE%` (диск D:, UNC) могут утечь в issue вместе с именем.

**Остаточный риск медиапарсера:** fuzz + ASan закрывают часть падений (`av_assert0` на пустом кадре уже ловили). Это не замена whitelist и не замена обновлений FFmpeg при CVE.

**Оценка безопасности: 6.5–7 / 10.**

Гигиена репозитория и панельного кода выше средней. Модель «чужой файл → FFmpeg в процессе NLE» без ограничений протоколов/размеров — главный незакрытый риск. Для плагина такого класса это ожидаемо, но исправимо.

## Производительность

Узкие места в основном измерены и задокументированы, а не угаданы.

1. **RGB-конверсия** — основная цена CPU-пути; YUV отдаётся хосту, когда можно.
2. **GPU→RAM** — аппаратный путь часто медленнее dav1d; Auto выбирает CPU при ≥8 логических процессорах.
3. **10-bit BGRA16** — ~4× дороже 8-bit; P010 быстрее, но на Premiere 26 сломан.
4. **Двойное открытие контейнера** на клип со звуком (+ ещё одно на async).
5. **Журнал:** две строки на кадр + `fflush`; уже ускоряли с 117 мкс до ~5 мкс на строку, но на скрабе это всё ещё шум.
6. **Перехват всех MP4:** `find_stream_info` на каждом импорте, даже H.264, который потом отдаётся Adobe. На больших библиотеках это лишняя задержка открытия.
7. **Кэш:** потолок 512 МБ на процесс, делится между клипами; `AETHER_CACHE_MB=0` снимает потолок (опасно).
8. **Черновой скраб** уже переведён на `SWS_FAST_BILINEAR` — это как раз не долг, а сделанное улучшение 1.3.0.

Рекомендуемый следующий замер: время `imOpenFile8` на обычном H.264 MP4 (отказ плагина) vs штатный импортёр — цена приоритета 100.

## Мусор и лишние файлы

В рабочей копии нет `.env`, `.pem`, `.log`, бинарников FFmpeg, SDK, `.prm`. `.gitignore` закрывает `build/`, `ffmpeg/`, `sdk/`, `installer/signing/`, `tools/signing/`, `.rnd`.

Не мусор, а осознанный объём: дубли README/docs RU+EN, release notes на каждую версию, пробные клипы не коммитятся (генерируются в CI).

Замечания по гигиене:

- `install.ps1` в корне — ручная установка, не лишний файл.
- Sample git hooks в `.git/hooks` — стандарт git, не часть продукта.
- В репозиторий не должны попасть `installer/signing/aether.p12` и `password.txt` (сейчас не попадают).

## Итог

Код выглядит как работа аккуратного лида, а не как свалка эксперимента. К немедленному исправлению относятся не секреты, а **ограничение того, что FFmpeg имеет право открывать и насколько большой кадр можно заявить**, плюс отказ от поиска DLL по PATH. После этого плагин будет соответствовать своему же уровню инженерной зрелости.
